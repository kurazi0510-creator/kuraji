# 残りの切替（先生の操作をまとめた手順）

新しい管理画面の主要な動作は確認済みです。繰り返し確認する必要はありません。
ここでは患者用Web予約とLINEを残したまま、古い公開GASの管理機能を閉じます。

**現在地（10/1）：LINE検証・実際の受信・Web申込の管理専用画面への表示を確認済み。元の旧公開v1〜7とv24は停止。給与用v30はデータ引継ぎまで保留。** 給与移行の準備と残る操作は [SALARY_CUTOVER.md](SALARY_CUTOVER.md)、最新の確認結果は [START_HERE.md](START_HERE.md) を参照。下記は全体の手順であり、完了済みの工程を最初から繰り返す指示ではありません。

## 1. LINE中継を用意する

CloudflareのWorkerに [line-webhook-worker.js](line-webhook-worker.js) を入れます。Workerの設定で次の2つをSecretとして保存します。

| 名前 | 入れる値 |
|---|---|
| LINE_CHANNEL_SECRET | LINE Developersのチャネルシークレット |
| GAS_WEBHOOK_URL | いま使っている公開GASのWebアプリURLに `?webhookKey=中継キー` を付けたURL |

中継キーは新しいランダムな長い文字列にします。同じ値を、いま使っている公開GASの「プロジェクトの設定→スクリプトプロパティ」の `LINE_WEBHOOK_FORWARD_KEY` に保存します。LINEトークンとは別の値です。チャットやGitHubへ貼り付けません。

LINE DevelopersのWebhook URLをWorkerのURLへ変更します。「検証」が成功し、院長のLINEから公式アカウントへメッセージを送って受信できることを確認します。成功前は次へ進みません。

## 2. 公開GASを制限版へ更新する

いま使っている公開GASのコードを [dist/Public.gs](dist/Public.gs) で更新します。新しい管理専用GASのコードへは貼りません。

「デプロイ→デプロイを管理→該当のWebアプリ→鉛筆→新バージョン→デプロイ」で、既存の患者用URLを保ったまま更新します。

患者用予約フォームの空き枠取得と予約申込、LINEの受信を確認します。テスト申込は実際に記録・通知されるため、院長自身のテストだと分かる内容を使います。

制限版の反映だけを調べるチェックも用意しました。

```
node security/verify-cutover.mjs 公開GASのWebアプリURL
```

このチェックは患者一覧を取得せず、書込み・LINE送信も行いません。実際の予約やLINE動作を確認した代わりにはなりません。

## 3. 古い公開デプロイを閉じる

同じGASの「デプロイを管理」にある、管理操作を許していた旧バージョンの公開Webアプリを確認します。患者用ページやLINEが参照していないことを確かめてから、該当する古いデプロイをアーカイブします。いま更新した患者用デプロイは残します。

別の「予約状況公開専用」GASも別途確認対象です。名称だけで削除せず、管理データを公開していないかをコードで確認します。

患者用予約確認ページは [confirm.html](../confirm.html) の確認コード方式へ更新します。本人確認済みの電話番号とLINEユーザーIDを公開GASの `BOOKING_LOOKUP_VERIFIED_LINKS` に設定するまでは、院への問い合わせへ案内します。

## 完了の条件

- 患者用Web予約の空き枠取得と申込が動く。
- LINEメッセージが中継経由で受信できる。
- 公開GASが制限版になり、旧版の管理APIを公開するデプロイが残っていない。
- 新しい管理画面が「自分のみ」のまま動く。

LINE再送では完了済みイベントの重複を6時間キャッシュで抑えますが、厳密な一回限りの処理を保証するものではありません。既存の自動通知トリガーは、新しい同種のトリガーと重複させません。

一部の外部設定とテストは先生の操作で実施済みです。こちらからの直接操作は未実施です。古い公開デプロイの閉鎖と予約確認ページの切替などが残っており、GitHubの修正だけで移行完了とは判断しません。
