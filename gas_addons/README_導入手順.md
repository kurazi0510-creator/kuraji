## 導入（1回だけ）
1. 管理用スプレッドシートを開く → 拡張機能 → **Apps Script**（既存のGASが入っているプロジェクト）
2. 左の「＋」→ スクリプト で、次の5つを**同じ名前で**追加し、中身を貼り付けて保存
   `kr_common` `kr_followup` `kr_backup` `kr_kpi` `kr_setup`
3. 左の歯車（プロジェクトの設定）→ タイムゾーンが **Asia/Tokyo** か確認
4. 関数選択で **`krSetupAll`** → 実行 → 権限を許可（Gmail送信・ドライブ・外部通信）
5. 完了メールとLINEが届けばOK。`krStatus` で ✅ が4つ並ぶことを確認

## 再来院フォロー（半自動）の使い方
**患者さんには、院長が「送信OK」にチェックした人にだけ送ります。完全自動はありません。**
1. 毎朝10:20ごろ、「今日送る候補」がシート **kr_followup_queue** に並び、メールとLINEでお知らせします。
2. 内容（患者名・次回予約の有無・送る文面）を見て、送ってよい行の **「送信OK」にチェック**。文面はその場で直せます。送らない人は空欄のまま。
3. 1時間以内に、チェックした行だけ送信されます。**送信の直前に、次回予約・交通事故・送信拒否/除外・再来院済み・期限切れを必ず再確認**し、当てはまれば送らず「結果」欄に理由（例：送信中止：次回予約あり）を記録します。
4. 結果は「送信済み／送信中止：〜／送信失敗」で残ります。同じ人・同じ来院日・同じタイミングは、表示も送信も1回だけです。

送るタイミング：初診の翌日（次回予約があっても送る）／初診7〜10日後（次回予約なし）／14日後（再診・次回予約なし）／45日後（全員・次回予約なし）。
安全装置：患者シートが空なら候補作成も送信も停止／1回30通・月100通まで／送信は9〜20時のみ／期限を過ぎた行は送らず閉じる。
- 文面確認：`krFollowupTestToOwner`（院長のLINEにだけ4種類を送信）
- 今日の候補を見るだけ：`krFollowupPreview`／今すぐ候補を作る：`krFollowupBuildNow`
- 文面を変える：スクリプトプロパティ `KR_MSG_1` / `KR_MSG_7` / `KR_MSG_14` / `KR_MSG_45`（`{name}`が患者名、改行は `\n`）。キューのシート上で1件ずつ直すこともできます。
- 送らない人：シート `kr_followup_exclude` に診察券No・患者名を追加、または患者シートの「再来院フォロー送信」列をFALSE
- 失敗した行を再試行：その行の「結果」欄を空にする
- 止める：`krFollowupSetMode('off')`（再開は `'queue'`）または `krStopAll`
- 将来、完全自動にする場合は、1〜2か月ミスがないことを確認してから、初診翌日だけを検討してください。

## バックアップ
- ドライブの「倉治整骨院_バックアップ」に週次コピー（最新8世代）、その中の「月次CSV」に月ごとのCSV（12か月）。
- 患者数・予約数が前回より **5件以上または10%超減る** と即アラート（61人→43人のような事故の検知）。
  異常中は古いバックアップを**自動削除しません**。意図した整理なら `krBackupAcknowledge` で解除。
- 復元：バックアップのコピーを開き、必要なシート（患者など）を現在のブックへ「コピー」して戻す。CSVからの復旧も可。
- 今すぐ試す：`krBackupNow`。成功時も通知がほしい場合はプロパティ `KR_BACKUP_NOTIFY_SUCCESS` = `1`

## 月次の数字
- 毎月1日8時台に先月分を集計。履歴はシート `kr_kpi_monthly`。
- 試す：`krKpiPreview("2026-09")`（送らず結果だけ表示）／送る：`krKpiForMonth("2026-09")`
- 見るのは「売上・新患」「次回予約率（目標60%）・新患の30日再来院率」「キャンセル率・稼働率」→来月の1アクションを1つ決める、の30分。

## 設定（スクリプトプロパティ・任意）
`KR_OWNER_EMAIL`（通知先。未設定ならGoogleアカウント宛）／`KR_BACKUP_FOLDER_ID`（保存先フォルダ指定）

## 注意・困ったとき
- ⚠ 既存の `setupAllTriggers()` は**全トリガーを削除**します。実行した後は必ず `krSetupAll` をもう一度実行（何回実行しても二重になりません）。
- 止めたいとき：`krStopAll`（追加機能のトリガー削除＋フォローOFF。既存のトリガーには触れません）
- エラーはシート `kr_system_log` に残ります。
- LINE_TOKENなどはスクリプトプロパティに保管（コードやGitHubに書かない）。
- テスト：`node gas_addons/tests/run_tests.js`（29項目）

## スマホ承認ページ・スタッフ用の一覧（approve_page フォルダ）
- `Code.gs` と `index.html`（郡さん用：文面を直して送信OK）、`view.html`（スタッフ用：見るだけ）を、**別の新しいプロジェクト**に貼る。
- スクリプトプロパティ：`AP_SHEET_ID`（スプレッドシートID）、`AP_TOKEN`（`apMakeToken`で作成）、`AP_VIEW_PIN`（スタッフ用閲覧パスワード）。
- ウェブアプリのデプロイを2つ：①自分のみ（郡さん用）、②全員（スタッフ用。`?v=1` 付きURL。パスワード必須・5回失敗で10分ロック）。
- 無題のプロジェクトに `KR_APPROVE_URL`（①のURL＋`?t=合言葉`）を入れると、毎朝のLINEにリンクが付く。
- `kanri.html` の「📨 フォロー候補」ボタンは、`KR_FOLLOWUP_VIEW_URL`（②のURL＋`?v=1`）を設定すると開く。
